### 8. CI 六连红的定位与修复（2026-09-21 追加，commit `a83e21f` / `e11b871` / `e0daa29`）

**症状**：`main` 上 6 次 CI 全红，但四个 job 里只有 **Android** 一个是红的，contract / windows / backend 每次都绿，且 Android job **从来没跑到过 Gradle**——它死在前置步骤上。逐层剥开是三个互相独立的败点，前一个修好后一个才暴露。

1. **`android-actions/setup-android@v3` 必失败**。该 action 按「latest」拼 cmdline-tools 下载地址 `https://dl.google.com/android/repository/commandlinetools-linux-13114759_latest.zip`，而 Google 改为**先同意服务条款才放行**该链接 → 固定 404，四个月来 Android job 一次都没构建过。上游已知问题 `android-actions/setup-android#513`（2025-12-17 开，2026-09-17 以「升级到 v4」结案，v4 默认 cmdline-tools 20.0）。
   **修法（未升 v4，省 300 MB 下载）**：删掉该 action，改成「缺什么补什么」——`ubuntu-latest` 镜像本就预装 Android SDK（cmdline-tools 12.0 + `platforms/android-35` + `build-tools/35.0.0` + 已接受许可，`ANDROID_HOME=/usr/local/lib/android/sdk`），预装齐全就 exit 0 零下载；将来镜像把 android-35 裁掉也能自愈，不会再挂死 CI。
2. **`apps/android/gradlew` 入库是 100644**。全仓库无任何文件带可执行位，`actions/checkout` 在 Linux 上按索引模式落盘 → `./gradlew` 立刻 Permission denied。修好败点 1 后立刻撞上。已 `git update-index --chmod=+x apps/android/gradlew`。
3. **阿里云 Maven 镜像对 GitHub 海外 runner 返回 502 Bad Gateway**。`settings.gradle.kts` 为国内拉依赖速度把三个 aliyun 仓排在最前，而 runner（Azure eastus，出口 IP `20.83.158.245`）访问它们一律 502 + 253 字节 HTML 错误页，KSP 的 plugin marker POM 因此解析不到，报错是：
   ```
   Plugin [id: 'com.google.devtools.ksp', version: '2.0.20-1.0.25', apply: false] was not found
     Searched in the following repositories:
       maven(https://maven.aliyun.com/repository/gradle-plugin)
       maven2(https://maven.aliyun.com/repository/google)
       maven3(https://maven.aliyun.com/repository/public)
       Google
       MavenRepo
       Gradle Central Plugin Repository
   ```
   **极具误导性**：六个仓库全被 Gradle 列为「已搜索」，含官方 MavenRepo 与 Plugin Portal，而该 POM 在官方源上实测就是 200（本地实测同样 6 个 URL 全部 200 → 镜像没坏，是地域封锁）。**修法**：`settings.gradle.kts` 按 `System.getenv("CI") != null` 分流，CI 只走 `google()` / `mavenCentral()` / `gradlePluginPortal()`，本地仍走 aliyun 三源在前。`onCi` 必须在 `pluginManagement {}` 与 `dependencyResolutionManagement {}` 各自块内声明——`pluginManagement` 早于脚本主体求值，顶层 `val` 会编译期 `Unresolved reference`。
   **腾讯云的 gradle 发行版镜像不受影响**（`mirrors.cloud.tencent.com/gradle/gradle-8.10.2-bin.zip` 从 runner 下载 100% 成功），无需改。

诊断结论来自一次性 workflow `diag-repos.yml`（`e11b871`，从 runner 上逐仓库 curl 同一个 KSP marker POM），用完即删。**修复后 run 7 `e0daa29` 四个 job 全绿。**

## 三、踩坑备忘（新增部分）

- **Cloudflare API + curl**：HTTP/2 流重置会导致 `curl error 92`，acme.sh 调用前写 `echo "--http1.1" > /root/.curlrc`。
- **acme.sh + sudo -E**：`HOME` 歧义会让 `account.conf` 写错位置、`--set-default-ca` 不生效并回退 ZeroSSL 失败；部署脚本里 `export HOME=/root`。
- **国内拉 GitHub 常被重置**：acme.sh 从 Gitee 镜像优先 clone。
- **nginx 1.18 不支持 `http2 on;` / `quic on;` 新语法**，用 HTTP/1.1 足够。
- **腾讯云未备案域名**：80/443 入向被拦截，非标端口（本项目 18443）可通行。
- **Android 12+ 前台服务**：后台启动抛 `ForegroundServiceStartNotAllowedException`，重试需退避（否则每 2~15s 空转耗电）。
- **Room 事务**：写库与 pending_ops 入队必须同事务，否则进程在两条语句之间被杀会出现「本地改了却永不同步」。
- **change_seq 全局自增**：换账号登录必须同时清零 pull 游标与 pending_ops，否则新账号历史永远拉不到、旧账号残留队列会把数据推到新账号名下。
- **标签配色**：必须按 UTF-16 码元求和而非码点，否则代理对（增补平面）字符在三端取到不同颜色。
- **`git-filter-repo` 选项名是 `--path-regex` 不是 `--path-rex`**，写错直接 `unrecognized arguments` 退出——`tools/repo-slim.sh` 曾因此从未真正跑通过。
- **不要用 `'.*\.jar$'` 这类宽泛剔除规则**：它会连 `apps/android/gradle/wrapper/gradle-wrapper.jar`（Android 构建必需）一起删掉。历史 jar 已全部落在 `tools/android` / `tools/android-dl` / `apps/android/app/build` 三条整路径规则内，无需额外正则。
- **filter-repo 会删掉 `origin` remote 与全部 `refs/remotes/origin/*`**，重推前要 `git remote add origin` + `git fetch origin` 重新建立；`refs/remotes` 清掉后 `origin/main..HEAD` 会报 `ambiguous argument`。
- **重写后测上传量要看差集**：`git rev-list --objects origin/main..HEAD` 在基点 hash 也变后会列出全部本地对象（虚高）；正确做法是 `comm -23` 对比「本地可达」与「远端可达」对象集合。
- **`bg_run` 落在 WSL，而该 WSL 无 `/bin/bash`**（`execvpe(/bin/bash) failed`），长任务改在前台 bash 工具里跑；`git-filter-repo` 若只有 python 模块无 CLI 入口，可在 `C:/Users/zibi/bin/git-filter-repo` 包一层 wrapper 指向 `Scripts/git-filter-repo.exe`。
- **`git cat-file --batch-check` 喂 `sha path` 形式会全报 `missing`**，那是解析怪癖不是对象缺失；先 `awk '{print $1}'` 去掉路径再喂。
